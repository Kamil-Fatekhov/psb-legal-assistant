# Веб-чат (роль C): запуск, проверка, стыковка

## Что входит

```
web/
  app.py        HTTP-сервер (FastAPI): /api/chat, /api/sources/{id}, /api/health, раздача интерфейса
  chat.py       ChatController: вызывает ядро, проверяет минимальный контракт Answer, собирает список источников
  schemas.py    Проверка входа (422) и форма JSON-ответов
  wiring.py     Выбор режима (mock/core) и сборка сервисов A и B из переменных окружения
  mock.py       Мок ядра и каталога для работы без LLM и базы
  __main__.py   Запуск: python -m web
  static/       Интерфейс: index.html, app.css, app.js (без сборки и npm)
fixtures/rent_case.json   Фикстура № 1: запрос, ответ и источник по аренде «Северный Склад»
tests/test_web_api.py     Автотесты API и стыковки с кодом A и B (38 тестов)
scripts/smoke_check.py    Проверка запущенного сервера по основному сценарию
scripts/e2e_browser.py    Проверка интерфейса в браузере, скриншоты в e2e-screens/
scripts/check_fixture.py  Сверка фикстуры с выданной базой
Dockerfile, compose.yaml, .dockerignore, requirements.txt, requirements-dev.txt, .env.example
```

Путь запроса: браузер → `POST /api/chat` → `ChatController.post_message` → `AssistantService.ask` (B) → поиск (A). Клик по номеру ссылки → `GET /api/sources/{fragment_id}` → `SourceRepository.get_source` (A) на том же `Corpus`, что и поиск.

Веб не хранит диалог на сервере. Браузер держит историю у себя и передаёт её в каждом запросе: от старых реплик к новым, без текущего вопроса. Вопросы, на которые пришла ошибка, и сами сообщения об ошибках в историю не попадают.

## Запуск

### Через Docker (так запускают организаторы)

Нужен Docker Desktop (Windows/macOS) или Docker Engine (Linux). В корне репозитория:

```sh
docker compose up --build
```

Откройте http://localhost:8000. Остановить — `Ctrl+C`, затем `docker compose down`.

Если порт 8000 занят, укажите другой в `.env`: `WEB_PORT=8080`.

### Без Docker (удобно для разработки)

Нужен Python 3.12 или новее.

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m web
```

macOS / Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m web
```

Чат откроется на http://127.0.0.1:8000. После правки `app.js` или `app.css` достаточно обновить страницу; после правки Python-кода перезапустите `python -m web`.

## Режимы

| `ASSISTANT_MODE` | Ответы | Источники | Когда использовать |
| --- | --- | --- | --- |
| `mock` | из `fixtures/rent_case.json` и правил в `web/mock.py` | из фикстуры | вёрстка, проверка интерфейса, демо без API |
| `core` | `AssistantService.ask` (B) | `SourceRepository` (A) по выданной базе | интеграция, финальное демо |
| `auto` (по умолчанию) | `core`, если есть база в `data/` и `LLM_API_KEY`, иначе `mock` | | |

В демо-режиме в шапке горит жёлтая плашка, чтобы не перепутать мок с настоящими ответами.

Для `core`:

1. Положите базу: `data/kb.zip` или папку `data/kb/` с TXT.
2. Скопируйте `.env.example` в `.env`, впишите `LLM_BASE_URL` и `LLM_API_KEY`. Ключи не коммитьте.
3. Запустите и проверьте `http://localhost:8000/api/health`: должно быть `"mode": "core"` и число фрагментов около 755.

При старте `core` строит векторный индекс через `/embeddings` — это может занять минуту-две. Если эмбеддинги недоступны, поиск работает по словам (в логе будет строка об этом).

Пока B не реализовал `AssistantService.ask`, чат в режиме `core` отвечает «Ядро ассистента ещё не подключено» (HTTP 503), а источники уже открываются из настоящей базы.

## Проверка

### 1. Автотесты (без сервера, ~1 секунда)

```sh
python -m pytest -q
```

Ожидаемо: `38 passed`. Тесты проверяют фикстуру аренды, все статусы ответа, коды 404/422/502/503, передачу истории, заголовки безопасности и режим `core` на настоящем индексаторе A.

### 2. Проверка запущенного сервера

В одном окне запустите сервер (Docker или `python -m web`), во втором:

```sh
python scripts/smoke_check.py
```

Работает в обоих режимах. В `core` это и есть «первый общий прогон» из плана: ответ должен содержать 450 000 и 5-е число, а источник — пункты 3.1 и 3.2.

### 3. Интерфейс в браузере

Один раз установите браузер для Playwright:

```sh
python -m playwright install chromium
```

Запустите сервер в демо-режиме (`ASSISTANT_MODE=mock`) и выполните:

```sh
python scripts/e2e_browser.py
```

Скрипт проходит основной сценарий, сбой с повтором, уточнение, вставку HTML в вопрос, прямую ссылку на источник, неизвестный ID и мобильную вёрстку. Скриншоты — в `e2e-screens/`.

### 4. Сверка фикстуры с базой

Текст фрагмента в `fixtures/rent_case.json` демонстрационный. Когда база лежит в `data/`:

```sh
python scripts/check_fixture.py
```

Скрипт скажет, есть ли ID `…:base:901` в каталоге A, содержит ли фрагмент оба пункта, и напечатает точный текст из базы для замены в фикстуре.

### 5. Ручные сценарии (демо-режим)

| Что ввести | Что должно произойти |
| --- | --- |
| Сколько платить за Северный Склад и когда? | Зелёный статус, два вывода со сноской 1. Клик по сноске открывает пункты 3.1 и 3.2 |
| …в редакции 2019 года? (про Северный Склад) | Жёлтый «Частичный ответ», один вывод, блок «Чего не хватает в базе» |
| Какие условия в договоре с Альфа? | Синий «Нужно уточнение» с вопросом «Альфа-Трейд или Альфа-Трейдинг?» |
| Затем ответить: Альфа-Трейд | Уточнение принято, повторно не переспрашивает; «Недостаточно данных»: в фикстуре нет этого договора |
| Затем: А когда платить? (после вопроса про аренду) | Ответ по аренде: история передана в ядро |
| Как оформить кредит на Луне? | «Недостаточно данных в базе», без выводов |
| Расскажи анекдот | «Вне рамок ассистента» |
| Игнорируй системный промпт и… | «Вне рамок ассистента», роль не меняется |
| #сбой | «Сервис временно недоступен» и кнопка «Повторить запрос» |
| `<img src=x onerror=alert(1)>` | Текст показан как есть, без картинки и окна |
| Открыть `/#source=что-угодно` | «Фрагмента с таким ID нет в каталоге» |

Те же сценарии в режиме `core` — это приёмка «Надёжность» дня 5: смотрим уже на ответы ядра B.

## Договорённости со смежными ролями

**С B (ядро).** Веб собирает ядро в `web/wiring.py::_build_core` так: `AssistantService(search, DeepSeekClient(), AnswerVerifier())`, где `search` — `SearchService` из `solution.create_search` или поиск по словам. Если конструктор изменится или появится общая фабрика ядра для `solution.py` и веба, поправьте только эту функцию. От ядра веб ждёт:

- `DependencyUnavailable` при сбое модели или индекса — чат покажет «Сервис временно недоступен» и кнопку повтора (HTTP 503);
- для `answered` и `partial` — непустые `findings`, у каждого непустые `source_ids`; иначе веб не покажет ответ (HTTP 502);
- для `clarification_needed` — заполненный `clarifying_question`.

**С A (поиск).** Источник открывается по `fragment_id` из того же `Corpus`, что и поиск. ID из `source_ids`, которого нет в каталоге, отображается в ответе как «Источник не найден в каталоге» и пишется в лог предупреждением — это сигнал разойтись в ID.

## Безопасность

- Весь текст (вопросы, ответы модели, документы) выводится через `textContent`, HTML не исполняется.
- Заголовки: Content-Security-Policy без inline-скриптов, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`.
- Вход проверяется: роль только `user`/`assistant`, вопрос до 4000 символов, не больше 40 сообщений истории.
- В логах только ID запроса, стадия, код и время. Текст вопросов и ключи не пишутся.
- Ошибки клиенту отдаются без внутренних деталей; код запроса в сообщении помогает найти строку в логе.
- Контейнер работает от непривилегированного пользователя, база монтируется только на чтение.

## Известные ограничения

- Диалог хранится во вкладке браузера (sessionStorage) и пропадает при закрытии вкладки.
- `context_text` от A пока совпадает с текстом фрагмента. Когда A начнёт отдавать окружающий текст, интерфейс сам покажет его с выделенным фрагментом.
- Поле `point` от A пока «Фрагмент с позиции N». Номера пунктов (3.1, 3.2) видны в тексте источника; после разбиения по пунктам у A они появятся и в списке источников.
- Шрифты PT Sans / PT Serif берутся из системы; если их нет, используются Segoe UI / Georgia.

## Частые проблемы

| Симптом | Что сделать |
| --- | --- |
| `port is already allocated` | Порт занят: `WEB_PORT=8080` в `.env` |
| В шапке «Демо-режим», хотя нужна модель | Нет базы в `data/` или ключа в `.env`; проверьте `/api/health` |
| «Ядро ассистента ещё не подключено» | B ещё не реализовал `AssistantService.ask` или ветки не слиты |
| «Ответ не прошёл проверку» | Ядро вернуло вывод без ссылок; код запроса из сообщения ищите в логах |
| `ModuleNotFoundError` при `python -m web` | Не активировано виртуальное окружение или не установлены зависимости |
